01 / Executive summaryPROJECT OVERVIEW

Executive summary

The project combines modality-specific image classifiers with Grad-CAM explanations and guideline retrieval to produce a structured, reviewable decision-support output.

Problem

  • Medical image interpretation requires specialist review and screening workloads can be large.
  • Image scores alone do not show where a model focused or how a finding relates to clinical guidance.
  • Unconstrained language models can state unsupported advice.

Proposed contributions

  • DenseNet-121 for chest X-ray labels and EfficientNet-B4 for skin lesions.
  • Grad-CAM overlays plus BioBERT/Chroma retrieval over supplied guideline PDFs.
  • Deterministic triage rules and a context-constrained summary behind FastAPI.
Key takeaway: The prototype organizes model evidence for clinician review. It does not confirm a diagnosis or replace care.

02 / Data and taskIMAGE CLASSIFICATION

Two modalities, two label spaces

The training pipeline uses public benchmark datasets and a separate output vocabulary for each modality.

NIH ChestX-ray14Frontal radiographs · 14 independent disease labels · CSV finding labels · patient-level fold splitting reduces leakage.
ISIC 2019Dermoscopy · 7 API-aligned outputs: MEL, NV, BCC, AKIEC, BKL, DF, VASC. Source AK maps to AKIEC; UNK is excluded.

Prediction

Independent sigmoid scores. Findings may co-occur; scores do not sum to one.

Imbalance

Focal loss down-weights easy examples; class-wise AUC is reported only when both label outcomes occur.

Split discipline

Patient-grouped NIH folds; stratified ISIC folds.

The supplied pitch names NIH ChestX-ray14 and ISIC. The implementation uses those datasets, not the CheXpert wording appearing in one pitch slide.

05 / Vision pipelineMODEL SELECTION

Modality-specific vision models

DenseNet-121 · chest radiographs

Dense feature reuse supports gradient flow and a compact feature extractor. Replace its classifier with a 14-output head for NIH findings.

Input $x\in\mathbb{R}^{3\times224\times224}$ → logits $z\in\mathbb{R}^{14}$ → $p_k=\sigma(z_k)$

EfficientNet-B4 · skin lesions

Compound-scaled convolutional features provide a higher-capacity dermoscopy backbone. Replace the final classifier with a 7-output head aligned to ISIC classes.

Input $x\in\mathbb{R}^{3\times224\times224}$ → logits $z\in\mathbb{R}^{7}$ → $p_k=\sigma(z_k)$
224 × 224Resize and ImageNet normalization in current inference
IndependentSigmoid outputs allow co-occurring findings
TransferImageNet initialization is optional during training

Preprocessing is an engineering default and needs validation against each dataset's acquisition protocol.

06 / Training designIMBALANCE · OPTIMIZATION

Training objective and optimization

Multi-label focal loss

$$p_t=y\sigma(z)+(1-y)(1-\sigma(z))$$ $$\mathcal{L}_{focal}=-\alpha_t(1-p_t)^\gamma\log(p_t)$$ $$\alpha_t=\alpha y+(1-\alpha)(1-y)$$

The code computes stable BCE-with-logits, then multiplies by $(1-p_t)^\gamma$. Easy examples contribute less, while hard examples retain more weight. Alpha balances positive and negative polarity.

Training recipe

  • RandomResizedCrop, horizontal flip, affine; ColorJitter for skin.
  • AdamW with decoupled weight decay.
  • CosineAnnealingWarmRestarts stepped per minibatch.
  • CUDA autocast and GradScaler when available.
  • Early stopping on validation macro ROC-AUC.
Cosine schedule: $\eta_t=\eta_{min}+\frac12(\eta_{max}-\eta_{min})(1+\cos(\pi T_{cur}/T_i))$. LR decays across a cycle and resets at $T_i$; $T_{mult}$ expands later cycles.

NIH folds split by patient; ISIC folds are stratified by class. Focal loss does not replace class-wise validation or calibration.

Component roles

  • PyPDFDirectoryLoader loads local PDF pages.
  • RecursiveCharacterTextSplitter builds overlapping chunks.
  • BioBERT embeds chunks and label queries.
  • ChromaDB persists and retrieves vectors.
  • OpenAI chat model synthesizes supplied passages only.
Grounding contract: Treat retrieved text as untrusted. State when context is insufficient; do not invent diagnoses or individualized treatments.
Requires relevant, licensed PDFs in data/guidelines/ and an indexed collection09

14 / Integration and next stepsDEPLOYMENT BOUNDARIES

Deployment path and future work

Current integration

  • POST /analyze accepts an image and optional modality.
  • Returns top label, confidence, probability map, triage, heatmap path, summary, and modality.
  • Checkpoints and local Chroma index load lazily.
  • Use explicit modality when the image type is known.

Before a real-world pilot

  • External multi-site test cohort and subgroup analysis.
  • Clinician review of thresholds, heatmaps, and summary claims.
  • Secure image handling, access controls, audit, retention policy.
  • Prospective workflow study, monitoring, rollback, and model governance.
